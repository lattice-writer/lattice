# 编译与排错

## 编译

按 `⌘S` 保存并编译。默认情况下，停止输入后 Lattice 也会自动编译（**设置 › 编辑编译 › 自动编译**）。编辑器上方的编译按钮显示结果和耗时，点击可以重新编译。

在命令面板（`⌘K`）中：

- **从头编译**：删除编译中间文件后重新编译。编译表现异常时可以试试。
- **清理缓存**：只删除中间文件。
- **停止编译**：停止正在进行的编译。

编译引擎（pdfLaTeX、XeLaTeX 或 LuaLaTeX）、shell escape 以及中间文件的位置在 **设置 › 编辑编译 › 编译** 中设置。项目里的 `latexmkrc` 会覆盖引擎设置。

## 查看并修复编译问题

编译失败时，编译按钮变红，PDF 上方弹出问题面板。每个问题标明文件和行号，显示附近的源码，并用通俗的话说明 LaTeX 报了什么错。

![编译失败：第 22 行的未知命令 \undefinedmacro，附带源码片段和「交给助手」](../images/zh-build-error.webp)

- 点击问题跳到对应行；用 `F8` 和 `⇧F8` 可以在问题之间切换。
- **日志** 显示 LaTeX 原始日志。
- **交给助手** 把这个问题交给 AI 助手；**一键修复** 让它修复所有问题。
- 缺少的宏包可以直接在问题里安装。

## 导出

- **导出 arXiv 提交包…**（项目菜单或 **文件** 菜单）生成一个可以独立编译的 ZIP。
- **导出 ZIP…** 导出整个项目，Overleaf 可以直接导入。
- PDF 面板的菜单可以保存编译好的 PDF。

## Typst 文档

原生版 Lattice 也能编写和编译 [Typst](https://typst.app) 文档（`.typ` 文件）。`.typ` 文件打开即有语法高亮。Typst 编译器需要另外下载一次，这样不用 Typst 的用户也不会多占空间。

- **下载 Typst 支持**：第一次编译 Typst 文档，或开始边写边编译时，Lattice 会询问是否下载 Typst 支持，这是一次性下载，约 22 MB。选择 **下载** 会下载它（搭载 Apple 芯片的 Mac）、校验签名后继续编译。选择 **以后再说** 则保持原样，文件只有语法高亮；在重新打开 Lattice 之前，输入时不会再询问，下次编译时会再次询问。应用更新后，Lattice 会自动下载对应版本。**设置 › 编辑编译 › Typst 支持** 中可以下载、移除或重新下载。

- **新建**：创建项目时选择 **Blank Typst document**，或在项目面板的 `+` 菜单中选择 **新建 Typst**。打开的文件夹如果没有 LaTeX 文档、但有 `main.typ`（或引入其他文件的那个 `.typ`），就会编译这个文件。
- **编译与预览**：`⌘S`、编译按钮和自动编译与 LaTeX 相同。Typst 还会边写边编译：停止输入片刻后，PDF 就会显示刚才未保存的修改，并保持原来的页码和滚动位置。
- **错误**：编译按钮和问题面板显示 Typst 的错误与警告，并标明文件和行号，点击即可跳到对应行。
- **源码与 PDF**：在 PDF 中双击某处，光标就会跳到源码中对应的那一行，`#include` 进来的文件也可以；按 `⌘⇧J` 则在 PDF 中标出光标所在的行。尚未保存的修改也算在内；需要先编译一次文档。
- **字体与包**：可以使用系统字体，以及 Typst 自带的字体（Libertinus Serif、New Computer Modern、DejaVu Sans Mono）。`#import "@preview/…"` 第一次使用时会从 Typst Universe 下载包，之后离线也能用。
- **在 LaTeX 项目中**编译某个 `.typ` 文件时，只单独编译它，其他编译仍然编译原来的 LaTeX 论文。

Overleaf 同步和可视化编辑器目前只支持 LaTeX。
